# Amphoreus 分阶段落地记录

## 目标

把项目推进到可直接部署使用的状态：核心链路闭环、启动与验证命令清晰、
无阻断性缺陷、文档同步。问题优先原地最小侵入修复，不以回退代替解决。

## 阶段一：现状评估与隔离验证

- 检查源码、配置、README、真实数据目录和日志。
- `python3 -m compileall` 与 `python3 -m tools.selftest` 全通过。
- 在临时数据库 + 临时端口启动 HTTP 服务，逐一验证静态入口和全部 API。
- 不触碰 `data/world.db`，避免验证污染真实世界。

## 阶段二：可部署性修补

- 修正配置注释中不存在的 `restart` 命令，改为准确的停止 + 后台启动命令。
- 新增 `python3 main.py check`，串联语法编译、端到端回归、真实 HTTP 冒烟。
- 更新 README 的部署、验收与重启说明。

验证证据：`python3 main.py check` 全绿，包含 47 项回归与 13 个 HTTP 入口。

## 阶段二补充：真实运行闭环

- `python3 main.py daemon`：真实后台进程启动成功，PID 写入 `data/amphoreus.pid`。
- `python3 main.py status`：正确显示运行中、世界时刻、火种与事件数量。
- 默认端口 `8760` 实测：`/`、`/book`、四份静态资源与全部七个 API 均返回 200；API JSON 均可解析。
- `python3 main.py stop`：后台进程正常停止，PID 文件清理完成。

本机没有 `curl`，HTTP 验证改用 Python 标准库 `urllib.request`，未向项目引入依赖。

## 阶段三：后续优化准入条件

每次优化只聚焦一个明确目标，必须附验证命令或日志；不得破坏现有只读架构、
确定性演算和断点续跑。重大调整先在本文件记录动机、方案对比与结论。

## 阶段四：「如我所书」矢量复刻

动机：把界面从网页风格向游戏内档案靠拢，同时避免位图放大模糊。

方案：六件档案保留现有只读数据流，前端布局、配色、标签栏、卷册卡、命路卡
原地改造；所有图案通过开发期 Potrace 脚本描摹为 SVG，页面只加载矢量资源。
没有游戏客户端可供解包，因此参照公开 wiki 可核对的 CSS 取值与素材，不把
结果声称为逐像素审计。

英雄头像曾出现黑剪影。根因是彩色 PNG 直接 posterize 后，浅色区变成透明孔洞，
叠在深色卡片上就成近黑色。修复采用浅底深线的单色描摹：对亮度做线性拉伸、
显式阈值取线，生成金线纸面风格 SVG；这样保留面部和服饰轮廓，且不引入运行时依赖。

验证：

- `node --check web/codex.js` 与 `node --check web/codex-art.js`
- `python3 main.py check`（含 SVG 数量、有色路径、档案图标统一金色、页面仅引用 SVG）
- 浏览器截图：首页、英雄纪目录、命路页
- HTTP：默认端口 `/book` 返回 200，静态 SVG 可访问

截图证据放在 `docs/screenshots/`：桌面 1440×1000 的首页、英雄纪目录、命路页，
以及移动端 390×844 的目录页。曾有一次桌面目录截图捕获到淡入动画中途，画面整体偏暗；
根因是 headless 截图与 hash 路由切换后的 CSS 淡入时机竞争。修复方式是把视图淡入从
0.35–0.5 秒收敛到 0.12 秒，并保留 `prefers-reduced-motion` 下完全禁用动画的分支；
随后在独立 Chrome profile、`--virtual-time-budget=6000` 下重拍，四张截图均已复核亮度正常。
